# 📅 GitHub Activity Plan — 2026

A realistic, sustainable plan for building a strong software-development and AI/ML GitHub profile through genuine work.

> **Important:** This plan is for real engineering work only. Do not create fake commits, backdate commits, manipulate timestamps, or make meaningless changes just to increase the contribution graph.

## 🎯 Annual Goals

- Build **3–4 portfolio-quality projects** rather than many unfinished repositories.
- Practice **Python and Java** consistently.
- Solve and document **DSA problems** with explanations and tests.
- Run small, reproducible **AI/ML experiments**.
- Complete **2–3 data analytics projects**.
- Build and improve **web applications**.
- Make **small, genuine open-source contributions**.
- Regularly improve documentation, tests, refactoring, and project quality.
- Target roughly **4–5 genuine GitHub activity days per week**, but skip activity when there is no meaningful work to commit.

## 🗓️ Sustainable Weekly Rhythm

A normal week can use this pattern:

| Day | Activity |
|---|---|
| Monday | Python/Java practice + DSA |
| Tuesday | Main project feature |
| Wednesday | AI/ML, data analytics, or web development |
| Thursday | Tests, debugging, refactoring, documentation |
| Friday | Project integration + meaningful commit |
| Weekend | Optional learning, issue triage, open-source contribution, or rest |

**Typical weekly output:** 2–4 meaningful commits, sometimes more when a real feature is completed. A week with fewer commits is completely acceptable if the work is deeper.

# 📈 Contribution Philosophy

A strong GitHub profile is not a green-square competition. Prefer:

1. **One meaningful feature over five empty commits.**
2. **A tested fix over a cosmetic change.**
3. **A useful README over a generated wall of text.**
4. **A genuine PR over artificial activity.**
5. **A finished project over ten abandoned repositories.**
6. **Consistency over burnout.**

## Suggested annual range

A realistic year may produce roughly **100–160 meaningful commits**, depending on project depth and job-search workload. The number is a planning range, **not a target to force**. Some weeks should have fewer commits or no commits at all.

## 🚫 Never Do This

- Do not backdate commits.
- Do not create empty commits to fill contribution squares.
- Do not repeatedly edit whitespace or README text only for activity.
- Do not automate meaningless commits.
- Do not split one tiny change into artificial commits.
- Do not copy repositories or code without attribution.

---

# ⭐ Making the Profile Recruiter-Friendly

- Pin **4–6 strongest repositories**.
- Give every serious project a clear README.
- Include **problem → approach → architecture → setup → results → limitations**.
- Add screenshots or demos where they genuinely help.
- Keep commit messages descriptive, for example: `Add input validation for login API`.
- Use issues for real bugs and future work.
- Use branches and pull requests for meaningful feature work.
- Add tests to projects that claim production readiness.
- Keep dependencies and setup instructions current.
- Highlight measurable results when they are real: accuracy, latency, test coverage, dataset size, or performance.
- Keep the profile README concise and let dedicated project READMEs contain technical depth.
